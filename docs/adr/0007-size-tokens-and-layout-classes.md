# 尺寸令牌、文字角色与布局档位

界面尺寸此前散落为页面内的字面量 `px`：标题、菜单项、正文与设置内容栏宽各写各的，没有统一来源；同时存在把 `FontScale` 当全局倍率使用的尝试，导致文字超出容器。DPI 缩放本身由 GPUI 按逻辑像素处理，窗口也可自由缩放，因此需要的是稳定的尺寸来源与少量明确的档位，而不是流式排版或全局字号倍率。

定案：在 `crates/fragmenta/src/ui/tokens.rs` 集中定义语义尺寸令牌，全部使用逻辑像素，不使用 rem。文字分六个角色：文档标题、正文、阅读文本三个内容角色以设置中的内容字号（`editor_font_px` / `tile_font_px`，12–24px）为基准，分别取 +2 / 基准 / -2；区块标题固定 18、控件标签固定 14、元信息固定 12。内容字号只作用于三个内容角色，设置页、导航与按钮等界面角色不受影响，避免控件文字随字号溢出。（2026-10-25 修订：原 `FontScale` 三档改为设置页直接调整具体像素。）

布局以内容驱动为底：优先 `flex_1`、`min_w_0`、百分比与最大宽度，页面内容栏在窄窗口下自然收缩；断点只承担留白与少量结构决策。`LayoutClass` 分 Compact（< 900）、Regular（900–1399）、Wide（≥ 1400），页面四周留白依次 16 / 24 / 32。设置内容栏固定 640；主窗口默认 1080×720、最小 760×520（GPUI 居中时会把初始尺寸钳到显示器工作区）；侧栏收起 80、展开 180–420、默认 255；磁贴 360×480、最小 240×280；月历 272；对话框 380；toast 最大 360。间距阶梯 4 / 8 / 12 / 16 / 24 / 32，圆角 6 / 8。

响应式边界：窗口首次以 Compact 档进入时主窗口侧栏自动收起一次；此后窗口缩放不强制改写用户已选择的侧栏状态。截断策略：元信息与单行标签可截断，正文与说明换行；只有文档标题行设置最小高度，避免列表行随内容字号变化跳动。

验收采用人工方式：在 760×520、1080×720、1600×900 三种窗口尺寸与 12–24px 内容字号范围内检查设置页、笔记分栏、待办月历与磁贴，不新增自动化测试。
